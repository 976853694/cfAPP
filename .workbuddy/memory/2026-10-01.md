## 首次实跑报错修复（Android job）
- 根因：`android-actions/setup-android@v3` 内部执行 `sdkmanager tools`，而 runner 镜像的 cmdline-tools 16.0 已移除 `tools` 包 → `Failed to find package 'tools'` + exit code 1，job 在 Gradle 启动前就崩了。
- 修复：**删除该 action**（ubuntu-latest 镜像自带完整 Android SDK，`ANDROID_HOME=/usr/local/lib/android/sdk`）。改为自写 "Set up Android SDK" 步骤：探测 SDK 路径 → 写 `ANDROID_HOME`/`ANDROID_SDK_ROOT` 到 `$GITHUB_ENV` → 写 `apps/android/local.properties` 的 `sdk.dir` → 按 `cmdline-tools/latest|bin|*/bin` 顺序找 sdkmanager → `--licenses` + 装 platform-tools/platforms;android-36/build-tools;36.0.0（失败只告警，交由 AGP 自动下载）。
- 顺带修掉会误导诊断的 Job summary：`steps.sign.outputs.generated` 为空时会误报「取自 Secret」，改为 case 分支显式区分 true/false/未执行。
- 经验：GitHub Actions 里 `${{ }}` 空值不会报错但会让 `&&`/`||` 兜底表达式给出假结论，排查时别信 summary，要看实际步骤是否执行。
- 排查日志技巧：日志超长时先 grep `##\[group\]Run |Error|Warning|FAIL` 定位，再定位到具体步骤。

## 第二次实跑报错修复（keystore 口令生成）
- 根因：`set -euo pipefail` 下 `STORE_PW="$(tr -dc 'A-Za-z0-9' < /dev/urandom | head -c 32)"` —— `head` 读够即退出，写端的 `tr` 收到 SIGPIPE（tr: write error: Broken pipe），`pipefail` 让整条管道非 0，`set -e` 终结步骤。本机复现退出码 = 141。
- 修复：改为 `openssl rand -hex 16`（主），`python3 secrets.token_hex(16)`（备），`head -c 32 /dev/urandom | od -An -tx1 | tr -d ' \n'`（再备，此写法 head 是读端不会触发 SIGPIPE）。
- 顺带修同级隐患：`find ... | head -n1` → `find ... -print -quit`（否则 find 同样 SIGPIPE，修完口令后立刻会踩到）。
- 通用规则：**GitHub Actions 的 `run` 默认 shell 是 `bash -e`，配合脚本内的 `set -o pipefail`，任何 `生产者 | head/tail -n1` 写法都可能导致 SIGPIPE 误判失败**。用 `grep -m1` / `find -quit` / `|| true` 替代。
